# LIBERO 单任务策略重跑与对比方案

本文件保留第一轮对比方案。旧结果、代码和实验总结全部保留；新结果写入 `myexperiment/results_v2/`。

**后续实现更新**：共用 split 文件、独立训练/环境/采样 seed、统一 rollout 参数、ACT 按 val_prior_mse 选 best、Sequence/ACT 缓存和无 CVAE 的 deterministic ACT 已接入。原六组可增加 deterministic ACT，变为 7 组 × 3 seeds = 21 次训练。训练恢复明确暂不做。下文“待实现”检查表为设计时的记录，当前状态和新命令以 [统一协议与确定性 ACT](统一协议与确定性ACT.md) 为准；未启动正式重跑。

## 1. 先明确这次要回答的问题

这几条路线值得保留：单步 BC → Chunk MLP → Sequence Transformer → 小型 ACT/CVAE → Flow Matching。暂时不需要继续增加模型。

把问题拆开：

1. 预测未来 K 步本身有没有帮助？同一个 Chunk MLP，比较 K=1 和 K=10，均每步重规划、只执行第一个动作。
2. temporal aggregation（TA）有没有帮助？同一份 K=10 权重，比较关闭和打开 TA。
3. 历史观测有没有帮助？同一种 Sequence Transformer，比较 H=1 和 H=5。
4. 不同模型整套方案的效果如何？固定相机、数据、预算和执行规则，比较 Chunk、Sequence、ACT 和 Flow。
5. 相机和生成式动作头是否值得增加计算量？后续分别做相机消融和动作头消融。

问题 4 是系统方案比较。当前编码器和模型结构不完全相同，不能把性能差异全部归因于“注意力”“CVAE”或“流匹配”。要回答机制问题，需要更严格的匹配实验。

## 2. 现有结果可以保留，但不能直接作为新主表

历史记录中，Chunk K10+TA 为 29/40，Sequence H5 为 31/40，ACT H5 为 13/40，ACT H10 为 36/40。这些结果说明路线能跑通，尚不足以证明 ACT 必然优于 Sequence，或 H10 必然更好。

主要限制：单训练 seed；训练轮数、学习率和历史长度不同；旧 rollout 的步数存在 250/270 两种设置；旧 ACT 按带真实未来动作辅助的后验重建误差选择 best，新 ACT 已按纯观测推理的 `val_prior_mse` 选择。新旧结果不能混成一张严格对比表。

40 次测试中，多成功一次就是 2.5 个百分点。29/40 与 31/40 只差两个 episode，应先检查重复训练和逐场景结果，再讨论改进是否稳定。

## 3. 重跑前应补齐和改进什么

### 3.1 主对比前必须统一

| 检查项 | 当前情况 | 处理办法 |
|---|---|---|
| 数据划分 | Chunk、Sequence、ACT 已分开 split seed 与训练 seed；原 BC 仍共用 seed | 主表用 Chunk K1 作为单步 BC；原 BC 若参加多 seed 正式比较，先补独立 `--split-seed` |
| 划分证据 | checkpoint 保存 train/val demo 名单 | 固定 split0；逐组核对名单完全一致，最好另存公共 split manifest，而不只相信 seed 相同 |
| 推理协议 | rollout 参数、seed 支持不一致 | 统一环境 seed、初始状态索引、稳定步数、最大步数、成功判据、预处理和动作裁剪；Chunk/Sequence 尚需补 seed 参数 |
| 权重选择 | 新 ACT 用 prior MSE；其他模型用验证动作 MSE | 只用不输入真实未来动作的预测指标选 best；禁止根据最终测试成功率挑 epoch |
| 指标归约 | chunk mask 指标按 batch 样本数累加 | 离线 chunk 指标应累计有效动作误差总和/有效动作数，避免尾部 mask 和 batch 组成影响权重；另报各模型共有的第一步动作 MSE |
| 训练预算 | 默认 epoch、lr、优化器不同 | 显式指定，不使用默认值；完成规定预算，记录实际 epoch 与 optimizer updates，禁止看 loss 手动提前停作为正式实验 |
| 可复现记录 | 配置在 checkpoint，环境和代码版本记录不足 | 保存命令、配置、代码快照/提交与 diff、依赖、数据哈希、split 名单、训练时长和最终状态 |

即使同一数据集、相同 epoch，各架构也不保证相同训练耗时。这里比较相同数据遍历预算，同时报告计算成本；如果训练样本数或 batch 策略改变，必须重新核对更新次数。

### 3.2 很值得做，但不是继续堆模型

- **Sequence/ACT 数据读取优化**：`LIBEROSequenceChunkDataset.__getitem__` 当前先读取整条 demo，再截取历史与动作。改成只读取需要的窗口，或者按 demo 缓存；不能缓存打开的 h5py 对象后交给 spawn。先测 data time / GPU 利用率，别直接靠增加 worker 数解决。
- **训练恢复**：保存原子写入的 best 和 last；last 包含模型、优化器、AMP scaler、epoch 和随机状态。现在有 Ctrl+C 的 metrics 保存，不等于支持完整断点续训。
- **模型配置完整性**：pool size、相机、H/K、动作头、视觉表示必须保存在配置并由 loader 恢复。旧 BC 1×1/4×4 池化权重不能直接当成当前固定 2×2 模型加载。
- **共享编码器用于严格机制比较**：当前 Chunk 默认 2×2 pooling，Sequence 为 1×1 pooling，state encoder 也不同。主表可比较整套方案；要声称 Transformer 本身带来增益，应先统一 CNN、pooling、state features，再重训。

### 3.3 ACT / Flow 需要额外澄清

1. 当前 ACT 是小型实现，包含 CVAE 和 action-query decoder，但使用小 CNN、MSE 等设置，不是原论文配置的完全复现。
2. 当前 Flow 分支没有 CVAE，因此 ACT→Flow 同时改变生成目标和潜变量路径。应补一个**同 ACT observation encoder/decoder、训练推理都无 CVAE 的确定性 MSE 头**，再与 Flow 比较。此基线尚未实现，不能用 `--kl-weight 0` 替代：KL 置零仍保留读取真实动作的后验。
3. ACT 主表固定 `global_pool`，暂不混入 spatial tokens。空间 token 可以以后单独消融。
4. 若做纯图像实验，需检查 CVAE posterior 是否仍读取 state；当前 posterior 路径存在此输入，不能直接把 image 模式视为训练全程不使用 state。
5. 双相机目前是 RGB 通道拼接成 6 通道，不是分别编码后做跨相机 attention。可以先作为工程基线；若失败，再比较独立/共享 backbone 加相机标识 token，不预设双相机一定更好。

## 4. 冻结公共协议

| 项目 | 本轮约定 |
|---|---|
| 任务 | LIBERO_SPATIAL，task 8；运行前打印任务名核对 |
| 数据 | `libero/datasets/libero_spatial/pick_up_the_black_bowl_next_to_the_plate_and_place_it_on_the_plate_demo.hdf5` |
| 数据划分 | 按完整 demo 划分，40 train / 10 val，split seed=0；统计量只由 train 计算 |
| 训练 seed | 0、1、2；固定数据划分，不取代 split seed |
| 主表输入 | agentview + 9 维本体状态，84×84；无增强，归一化方式一致 |
| 主表预算 | 50 个完整 epoch、batch=64、lr=1e-4、weight decay=1e-4；Chunk/Sequence/ACT 使用 AdamW |
| Transformer 设置 | d_model=128，heads=4，layers=2，dropout=0.1；ACT latent=32、KL weight=10 |
| 执行 | 每步重新预测；K>1 主表开 TA，decay=0.2、history_size=K；另报相同权重关闭 TA |
| 环境 | 固定官方初始状态顺序，稳定 5 个零动作，动作 clip 到 [-1,1]，max_steps=270 |
| 正式 rollout | 每个 checkpoint 使用全部 50 个官方初始状态，逐个保存结果；先核对实际数量，若不是 50 则用实际数量且全组一致 |
| 随机策略 | 主表环境/采样 seed 固定 0；Flow 额外用采样 seed 1、2 检查敏感性，不能挑最好的 seed 汇报 |
| 精度 | 显式记录；ACT 可用 AMP，其余当前为 FP32。严格计算/数值比较前再统一，不能默认所有模型都用了 AMP |

lr=1e-4 是保守起点，不保证每种模型的最优超参数。先用 seed0 检查训练是否正常；若需要调参，每个模型最多尝试同样数量（例如 1e-4、3e-4 两档），只按验证集指标选择，然后冻结，再跑正式的 3 个 seed。调参运行与正式运行分目录。

这里沿用历史实验的 270 步以便建立一致的新基线，不声称这是官方统一时间上限。

**测试用途约束**：全部 50 个初始状态作为固定最终评测集合，不用它们反复调参。如果已经根据它们改过模型，本轮只能叫已知任务/场景上的工程比较，不能声称独立测试泛化。要更严格，先为所有 rollout 增加统一的 init-state 索引列表，用 0–9 调试、10–49 最终评测；不能只给 ACT 分组而其他模型仍跑前 40 个。

## 5. 第一阶段：18 次训练的主对比

先每组跑 seed0 做训练和闭环冒烟检查，协议冻结后补 seed1/2。主表只使用协议冻结后的运行。

| ID | 模型 | H | K | 主表执行 | 要回答的问题 |
|---|---|---:|---:|---|---|
| M0 | Chunk MLP，作为单步 BC | 1 | 1 | first | 与 K10 共用代码和编码器的单步基线 |
| M1 | Chunk MLP | 1 | 10 | TA 0.2 | chunk + 融合的整套收益 |
| M2 | Sequence Transformer | 1 | 10 | TA 0.2 | 无历史时的 Transformer 方案 |
| M3 | Sequence Transformer | 5 | 10 | TA 0.2 | M2→M3 隔离历史长度作用 |
| M4 | 小型 ACT/CVAE | 5 | 10 | TA 0.2 | 与 M3 比较完整模型方案 |
| M5 | ACT observation + Flow | 5 | 10 | TA 0.2，Euler 10 步 | 与 M4 比较生成方案与成本 |

6 组 × 3 seeds = **18 次训练**。每份权重主表测 50 个场景，共 900 个 episode。

额外对 M1–M5 的同一份 best 关闭 TA，不再训练：5×3×50=750 个 episode。因此主表及 TA 消融共 1,650 个 episode；视频保存也会消耗时间和空间。

- M0 first 与 M1 first：主要检查预测 chunk 的训练收益。
- M1 first 与 M1 TA：同权重检查融合收益，不把两者混在一起解释。
- M2 与 M3：同结构检查历史观测收益。
- M1 与 M2、M3 与 M4、M4 与 M5：当前只能解释为整套模型方案比较。
- M0 不是原 `train_bc.py` 的历史结果；原 BC 若要保留为独立参考，补 split seed 后另跑，不把名称相同当作权重或结构相同。

## 6. 第二阶段：按问题追加，避免全排列

### A. 摄像头：优先只对一个选定模型做

选择验证集指标及预算满足要求的一个模型，固定 H/K/动作头，比较 `none / agentview / wrist / both`。主表已有 agentview，新增 3 种 × 3 seeds = **9 次训练**。第一轮总计 **27 次训练**。

`none` 表示仅本体状态；其他三种都仍保留本体状态。这里研究的是增加视觉/相机视角的收益，不是 image-only vs state-only 的完整模态实验。

如果确实要回答“相机对每类模型是否都有帮助”，对 M0、M1、M3、M4、M5 全部做四种相机，各 3 seeds：这五组共 60 次训练，加 M2 的 3 次，共 **63 次训练**，包含主阶段；不要一开始就全部启动。

### B. K 与 H：有明确疑问再做

- Chunk MLP 补 K=5，3 seeds；与 M0/M1 构成 K=1/5/10。每份 K5 权重测试 first 和 TA。
- Sequence 补 H=10，3 seeds；与 M2/M3 构成 H=1/5/10。
- ACT 若要验证旧 H10 高分是否稳定，补 H=10、3 seeds，与 M4 的 H5 比较；不能用旧 seed0 权重代替。
- 以上每项各加 3 次训练，不需要把所有 H、K、相机组合相乘。

### C. 动作头：真正隔离 Flow 的作用

先实现第 3 节的确定性 ACT decoder，并统一 observation encoder、H5/K10、相机、decoder 尺寸、训练预算及预测动作数。

比较 deterministic MSE / CVAE / Flow，均做 3 seeds。新增确定性基线至少 3 次训练；如果为匹配架构修改了现有模型，就重训全部三组，不能继续沿用架构不匹配的旧权重。

Flow 的 Euler steps=5/10/20 在同一 checkpoint 上测，不重新训练。主结果仍固定 10；其他步数报告成功率与延迟的权衡，不能测完后只报最高值。生成分布可以具有多模态，因此一次采样的动作 MSE 不一定能完整衡量质量；同时保留闭环结果和采样敏感性。

### D. 跨任务：比继续把单任务调高几个点更有价值

单任务路线稳定后，预先指定另外 2 个不同类型任务，仅比较 M0、M3 和一个候选模型，每任务各训 3 seeds，即新增 18 次训练。单任务脚本分别训练，不声称这是多任务或语言条件策略。

若想声称单任务结论适用于整个 LIBERO_SPATIAL，应覆盖整套任务，而不是挑表现好的任务汇报。

## 7. 当前代码可执行的训练模板

下列命令使用已有参数；适合冒烟检查及按当前实现做系统比较。第 3 节的统一 seed/指标等修改完成前，不将其输出标成最终严格实验。输出目录由训练器自动创建，旧目录不受影响。

在同一个终端运行；服务器先确认 GPU 物理编号和使用安排。`CUDA_VISIBLE_DEVICES=2` 只是之前服务器空闲 A100 的示例，不代表现在仍空闲。

```bash
cd /home/zx/LIBERO
conda activate libero
export DATASET="/home/zx/LIBERO/libero/datasets/libero_spatial/pick_up_the_black_bowl_next_to_the_plate_and_place_it_on_the_plate_demo.hdf5"
export RUN_ROOT="/home/zx/LIBERO/myexperiment/results_v2"
export CUDA_VISIBLE_DEVICES=2
```

服务器上应将仓库、数据和 RUN_ROOT 改为服务器实际路径。单卡顺序执行以下训练，不用 DDP。

M0/M1：

```bash
for seed in 0 1 2; do
  for k in 1 10; do
    python myexperiment/actionchunk/train_action_chunking.py \
      --dataset "$DATASET" --split-seed 0 --seed "$seed" \
      --chunk-size "$k" --pool-size 2 --cameras agentview \
      --epochs 50 --batch-size 64 --lr 1e-4 --weight-decay 1e-4 \
      --image-size 84 --num-workers 0 \
      --output "$RUN_ROOT/task8/chunk_h1_k${k}_agentview/split0_seed${seed}" || break 2
  done
done
```

M2/M3：

```bash
for seed in 0 1 2; do
  for h in 1 5; do
    python myexperiment/actionchunk/train_sequence_transformer.py \
      --dataset "$DATASET" --split-seed 0 --seed "$seed" \
      --history-length "$h" --chunk-size 10 --cameras agentview \
      --d-model 128 --num-heads 4 --num-layers 2 --dropout 0.1 \
      --epochs 50 --batch-size 64 --lr 1e-4 --weight-decay 1e-4 \
      --image-size 84 --num-workers 0 \
      --output "$RUN_ROOT/task8/sequence_h${h}_k10_agentview/split0_seed${seed}" || break 2
  done
done
```

M4/M5：

```bash
for seed in 0 1 2; do
  for head in transformer flow; do
    python myexperiment/actionchunk/train_act.py \
      --dataset "$DATASET" --split-seed 0 --seed "$seed" \
      --history-length 5 --chunk-size 10 --cameras agentview \
      --action-head "$head" --flow-steps 10 \
      --visual-representation global_pool --observation-mode both \
      --d-model 128 --num-heads 4 --num-layers 2 --dropout 0.1 \
      --latent-dim 32 --kl-weight 10 \
      --epochs 50 --batch-size 64 --lr 1e-4 --weight-decay 1e-4 \
      --image-size 84 --num-workers 0 --amp \
      --output "$RUN_ROOT/task8/act_${head}_h5_k10_agentview/split0_seed${seed}" || break 2
  done
done
```

Flow 不使用 CVAE/KL；这里显式写出的 latent/KL 参数只对 transformer 分支有效。正式自动批处理还应检查 metrics 中实际完成 epoch；现有训练器捕获 Ctrl+C 后可能正常退出，不能只用进程退出码判断训练完成。

## 8. rollout 命令示例

以下是 seed0 示例，其他训练 seed 更换 checkpoint 和 output。先确认任务名和官方初始状态数量。各组沿用相同物理时间上限，不能因某模型动作慢而额外增加步数。

Chunk K10 + TA：

```bash
python myexperiment/actionchunk/rollout_action_chunking.py \
  --checkpoint "$RUN_ROOT/task8/chunk_h1_k10_agentview/split0_seed0/best.pt" \
  --benchmark LIBERO_SPATIAL --task-id 8 --num-rollouts 50 --max-steps 270 \
  --temporal-aggregation --aggregation-decay 0.2 --history-size 10 \
  --output "$RUN_ROOT/task8/chunk_h1_k10_agentview/split0_seed0/eval_ta02"
```

Sequence H5 + TA：

```bash
python myexperiment/actionchunk/rollout_sequence_transformer.py \
  --checkpoint "$RUN_ROOT/task8/sequence_h5_k10_agentview/split0_seed0/best.pt" \
  --benchmark LIBERO_SPATIAL --task-id 8 --num-rollouts 50 --max-steps 270 \
  --temporal-aggregation --aggregation-decay 0.2 --history-size 10 \
  --output "$RUN_ROOT/task8/sequence_h5_k10_agentview/split0_seed0/eval_ta02"
```

Flow H5 + TA（ACT transformer 权重使用同一脚本，更换路径，去掉 flow steps 即可）：

```bash
python myexperiment/actionchunk/rollout_act.py \
  --checkpoint "$RUN_ROOT/task8/act_flow_h5_k10_agentview/split0_seed0/best.pt" \
  --benchmark LIBERO_SPATIAL --task-id 8 --num-rollouts 50 --max-steps 270 \
  --seed 0 --flow-steps 10 \
  --temporal-aggregation --aggregation-decay 0.2 --history-size 10 \
  --output "$RUN_ROOT/task8/act_flow_h5_k10_agentview/split0_seed0/eval_ta02_sampling0"
```

关闭 TA：去掉 `--temporal-aggregation`，输出换为 `eval_first`。这表示每步预测并只执行最新 chunk 的第一个动作，**不表示开环连续执行 K 步**。后者是另一种控制策略，当前不能直接当作同一消融。

M0 用 Chunk rollout 脚本，加载 K1 权重，不开 TA。Chunk/Sequence 当前没有统一 rollout seed 参数，不能直接给它们追加 `--seed`；该能力需要按第 3 节先补齐。

建议一个配置一个目录，一个训练 seed 一个子目录，评测结果放在对应 checkpoint 下：

```text
myexperiment/results_v2/

  splits/task8_split0.json
  summary.csv
  task8/

      split0_seed0/
        command.txt
        config.json
        environment.txt
        train.log
        metrics.json
        best.pt
        last.pt
        eval_first/
        eval_ta02/
```

这是目标目录规范，不代表当前训练器会自动生成上面所有文件。当前主要已有 best.pt、metrics.json 和 rollout 产物，其余记录/恢复能力需要补齐。

主表至少记录：

| 模型 | H/K | 相机 | 训练 seed | best epoch | 实际 updates | 第一动作 val MSE | 成功数/50 | 成功率 | 推理 p50/p95 ms | 训练时间/显存 |
|---|---|---|---|---|---|---|---|---|---|---|
| 待运行 | | | | | | | | | | |

汇报规则：

- 先列 3 个训练 seed 各自成功率，再列均值 ± 样本标准差，不只报最好的一次。
- 保留每个 init-state 的成功/失败及轨迹长度，用配对场景找模型之间的具体差异。
- 3 个 seed 各 50 场景共享初始状态，不能把 150 次当作完全独立场景来给出过于乐观的置信区间。训练 seed 稳定性、场景差异、Flow 采样差异分别报告；小差异先视为不确定。
- chunk 全序列 MSE 的预测范围随 K 改变，不能直接把 K1 和 K10 的 loss 大小当成模型排名；Flow velocity loss、ACT KL 和普通动作 MSE 也不能直接互比。
- 延迟在同一 GPU、batch1、固定 H/K/相机下测量，预热并同步 CUDA；分别报告模型推理和预处理/TA 在内的控制端耗时，视频编码另计。
- 抽样检查失败视频，分类为接近失败、抓取失败、掉落、放置失败、超时等。不要只靠验证 loss 判断下一步该改哪里。

## 10. 推荐执行顺序与停止条件

1. 不清理旧结果，先补齐第 3.1 节协议缺口；做微型数据过拟合、归一化往返、history/chunk 边界、相机对应和 rollout 预处理一致性检查。
2. 六组各做一次短冒烟，确认训练、best 选择和 rollout；对 Sequence/ACT 测数据读取耗时。短冒烟单独存放，不进主表。
3. 冻结协议，完成主对比 18 次训练和同权重 TA 消融。
4. 优先完成一个模型的四相机实验，新增 9 次；不要先启动 63 次大矩阵。
5. 若 Flow/ACT 没有稳定收益，先检查先验/后验差距、采样方差、KL、数据管线和失败类型，再决定是否补确定性动作头或空间 token。
6. 如果多个模型在三个 seed 上都已接近成功率上限，或差异小于重复实验波动，转向更多任务/更难初始状态，不继续以小数点改进作为主要结论。

这轮目标是得到可信、可复现的比较，不要求复杂模型一定胜出，也不保证流匹配在 40 条训练 demo 上优于简单回归。
