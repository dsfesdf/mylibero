# 四模型双相机纯视觉对比

自动入口：[run_dual_camera_comparison.py](run_dual_camera_comparison.py)。它复用 `run_suite.py` 的任务完成检查、日志、跨机器路径恢复和结果汇总，并提供本轮专用默认配置。原通用入口的模型列表不变。

## 实验协议

| 项目 | 本轮固定设置 |
|---|---|
| 模型 | Sequence Transformer、小型 ACT/CVAE、确定性 ACT、ACT observation encoder + Flow |
| 输入 | 两路相机：agentview + eye-in-hand；6通道拼接；不输入真实机器人状态 |
| 历史/预测长度 | H=5，K=10 |
| 任务 | LIBERO_SPATIAL task8：黑碗 next to plate → 放到盘上 |
| 划分 | 公共 split.json，split seed=0，40 train / 10 val demo |
| 训练 seed | 全部为0；先筛选，不宣称已验证跨 seed 稳定性 |
| 训练 | 200 epochs，batch256，AdamW，lr=1e-4，weight_decay=1e-4，workers6 |
| 图像和 Transformer | 84×84，d_model128，heads4，layers2，dropout0.1 |
| 精度 | 四模型统一 FP32；本专用入口对 ACT 默认关闭 AMP |
| CVAE / Flow | latent32，KL weight10；Flow Euler10步 |
| 选 best | Sequence 验证 masked action MSE；ACT 三头使用纯观测推理 val_prior_mse |
| 闭环 | 全部官方初始状态、环境 seed0、采样 seed123、max_steps270、settle5 |
| 执行动作 | 主表统一 TA，decay0.2、history_size10；每步重新预测 |

共 **4 次训练、4 次 rollout 调用**。任务有50个初始状态时，共200个闭环 episode。默认只训练，不自动进入 rollout。若需 first/TA 同权重消融，首次训练前加 `--policies first ta`，则变为8次 rollout、400个 episode。

200轮、batch256沿用上一轮结果，不保证每个模型均已收敛；保留实际曲线和 best epoch。Sequence 与 ACT 的观测投影、decoder 等结构不同，这是完整方案对比；三种 ACT 头共享观测编码器设计，但 CVAE/Flow 的生成路径不同。

纯视觉实现：Sequence 用固定零 state 特征占位保留结构，不依赖真实机器人状态；ACT image 模式只融合视觉，CVAE posterior 的 state token 也是固定零输入。数据接口仍要求 HDF5 有 state 字段，但模型不使用真实 state 信息。旧单相机权重不能用于本轮双相机实验，需重新训练。

## 服务器训练

更新服务器代码，激活环境，从仓库根目录运行。先确认物理GPU编号2仍可用。

```bash
conda activate libero
cd /share/2026zx/LIBERO

python myexperiment/run_dual_camera_comparison.py \
  --dataset /share/2026zx/LIBERO/libero/datasets/libero_spatial/pick_up_the_black_bowl_next_to_the_plate_and_place_it_on_the_plate_demo.hdf5 \
  --output-root myexperiment/results_dual_camera/compare_seed0 \
  --gpu 2 --stage train --execute
```

脚本默认就包括两路相机、纯视觉、seed0、split0、lr1e-4、workers6、batch256、200轮，不必重复输入。去掉 `--execute` 可预览所有训练命令。脚本按模型顺序启动一个训练进程，不同时启动四个模型。

可覆盖 `--epochs`、`--batch-size`、`--num-workers` 等参数，但不同配置应使用新 output-root。默认 worker6 可能增加内存和进程传输开销，未必比 worker0/2 更快；本轮按你的要求固定为6。

每组训练完成检查实际epoch、best.pt后写 train.complete.json；未完成或异常立即停止，不自动覆盖旧目录，不支持中断epoch恢复。

## 距离分桶

Sequence 新增可选 `--distance-buckets`；本专用套件默认开启。ACT 原有分桶保持启用。两者现在共用 `distance_buckets.py`，算法、测量种子和边界一致。

1. 对全部官方初始状态分别 reset，设置相同的逐场景环境 seed，稳定5步。
2. 计算 `akita_black_bowl_1` 与 `plate_1` 的物体 body 中心三维欧氏距离，单位米。这里不是机器人末端到物体的距离。
3. 按全部初始状态的1/3、2/3分位数生成两个阈值：`d <= t1` 为near，`t1 < d <= t2` 为medium，其余far。
4. 报告每个桶的场景数量、成功数量和成功率，并记录逐初始状态距离/分桶/结果。即使只选部分场景测试，阈值也从全部初始状态计算，不随被测子集改变。

首次训练前可用 `--distance-thresholds 0.12,0.24` 指定固定米制阈值，四个模型共用；数字仅为格式示例，不推荐未经核查直接采用。默认使用与旧实验一致的三分位方法。相同距离的场景可能导致桶数量不完全相等，空桶成功率为 null。

距离测量会额外初始化全部场景，开始 rollout 前可能需要等待；它不执行策略，也不改变逐episode重置的动作采样协议。环境版本不同可能影响初始几何，正式对比应核对四模型记录的距离和阈值一致。
