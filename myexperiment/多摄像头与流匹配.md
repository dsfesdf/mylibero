# 多摄像头输入与 ACT 流匹配动作头

## 统一的相机选择

四个训练入口均新增 `--cameras`，默认 `agentview`，与原实验保持一致。

| 参数值 | 模型接收的图像 | 同时接收 state |
|---|---|---|
| `none` | 零路，不读取图像字段、不运行视觉编码器 | 是 |
| `agentview` | 一路外部相机 | 是 |
| `wrist` | 一路腕部相机 | 是 |
| `both` | 外部相机 + 腕部相机 | 是 |

数据中的 `agentview_rgb` 对应环境的 `agentview_image`；
`eye_in_hand_rgb` 对应 `robot0_eye_in_hand_image`。
双路图像分别缩放到相同尺寸，然后按 `[外部 RGB, 腕部 RGB]` 的顺序在通道维拼接，
组成六通道输入。CNN 首层学习两路信息的融合，后续编码器和历史序列接口保持一致。
这是通道融合，不是两套独立 backbone。单路为三通道，零路为空通道、只用状态特征。
ACT 的 `spatial_tokens` 分支处理融合后的视觉特征网格。

相机数量、名称和顺序属于模型配置：需要分别训练，不能把单路权重直接当成双路权重。
评测与 rollout 自动读取 checkpoint 的 `cameras`，无需再填写；旧 checkpoint 缺少该字段时
默认使用 `agentview`。零相机指策略不使用图像，仿真仍可渲染外部画面保存视频。

以下命令在仓库根目录、`libero` 环境执行。每个实验使用独立输出目录。

```bash
cd /home/zx/LIBERO
conda activate libero
export DATASET=libero/datasets/libero_spatial/pick_up_the_black_bowl_next_to_the_plate_and_place_it_on_the_plate_demo.hdf5

# 单步 BC：双路相机
python myexperiment/bc/train_bc.py \
  --dataset "$DATASET" --cameras both --epochs 30 \
  --output myexperiment/bc/outputs/bc_both_seed0

# Chunk MLP：双路相机
python myexperiment/actionchunk/train_action_chunking.py \
  --dataset "$DATASET" --cameras both --chunk-size 10 --epochs 30 \
  --split-seed 0 --seed 0 \
  --output myexperiment/actionchunk/outputs/chunk_both_seed0

# Sequence Transformer：双路相机
python myexperiment/actionchunk/train_sequence_transformer.py \
  --dataset "$DATASET" --cameras both --history-length 5 --chunk-size 10 \
  --epochs 30 --split-seed 0 --seed 0 \
  --output myexperiment/actionchunk/outputs/sequence_both_seed0
```

把 `both` 改成 `none`、`agentview` 或 `wrist`，并更换输出目录，即可做输入消融。
图像缺失会明确报错，不会静默补零冒充摄像头。
BC/Chunk 会缓存图像；双路输入会增加内存和显存开销，显存不足先降低 `--batch-size`。

## ACT 的两种动作头

`train_act.py` 新增：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--action-head transformer` | 默认 | 原 CVAE posterior + latent + Transformer decoder 动作回归 |
| `--action-head flow` | 可选 | 根据观测预测连续速度场，从噪声生成整个动作 chunk |
| `--flow-steps 10` | 10 | 流匹配推理的 Euler 积分次数 |

BC、Chunk MLP、Sequence 的动作头保持原定义；这次新增的 flow 分支位于 ACT。
两种分支各自训练并保存 checkpoint，不是同一个 checkpoint 在推理时任意切换生成算法。
旧 ACT 权重缺少 `action_head` 字段时，仍按 `transformer` 严格加载。

### 流匹配训练原理

对一个归一化的真实动作 chunk `a`，采样同形状高斯噪声 `epsilon` 和时间 `t∈[0,1]`：

```text
x_t = (1-t) * epsilon + t * a
目标速度 v_target = a - epsilon
v_prediction = FlowDecoder(x_t, t, observation_memory)
loss = masked_mean((v_prediction - v_target)^2)
```

flow decoder 将含噪动作、时间 embedding 和未来位置 embedding 编成动作 token，
通过 self-attention 建模 chunk 内的关系，再通过 cross-attention 读取观测 memory。
轨迹尾部的 padding 同时从速度损失和动作 token 的 key attention 中排除。
真实动作仅用于构造训练插值点及速度标签；rollout 不需要真实动作。

这个 flow 分支采用纯观测条件，不运行 CVAE posterior，也没有 KL loss；
`--latent-dim` 与 `--kl-weight` 在 flow 分支不参与生成目标。
Transformer 在这里仍用于参数化速度场，改变的是动作生成目标和采样过程。

推理从随机 `x_0` 开始，按 `N=flow_steps` 次迭代：

```text
dt = 1/N
x_(i+1) = x_i + dt * v(x_i, i/N, observation)
最后的 x_N -> 动作反归一化 -> temporal aggregation（如果启用）-> clip -> 环境
```

现有实现实际在归一化空间聚合，再反归一化；对固定均值和标准差的线性归一化，这与先反归一化
再加权平均等价。预测整个 chunk 后每个控制步执行一个动作，temporal aggregation 逻辑复用原实现。
积分次数越大，模型调用次数越多，不保证成功率单调提高。流采样带随机性，不能把速度场 loss
当成原 Transformer 的动作 MSE 来比较。

### 训练对照

```bash
# 保留的 Transformer/CVAE 分支
python myexperiment/actionchunk/train_act.py \
  --dataset "$DATASET" --cameras both --action-head transformer \
  --history-length 5 --chunk-size 10 --d-model 128 --num-heads 4 --num-layers 2 \
  --latent-dim 32 --kl-weight 10 --epochs 30 --batch-size 32 \
  --split-seed 0 --seed 0 --num-workers 0 \
  --output myexperiment/actionchunk/outputs/act_transformer_both_h5_seed0

# 新增的 Flow 分支
python myexperiment/actionchunk/train_act.py \
  --dataset "$DATASET" --cameras both --action-head flow --flow-steps 10 \
  --history-length 5 --chunk-size 10 --d-model 128 --num-heads 4 --num-layers 2 \
  --epochs 30 --batch-size 32 --split-seed 0 --seed 0 --num-workers 0 \
  --output myexperiment/actionchunk/outputs/act_flow_both_h5_seed0
```

可加 `--no-amp` 排查混合精度问题。四类策略均保留每 epoch 保存指标和 `Ctrl+C` 保存逻辑。

### 离线评测和 rollout

```bash
python myexperiment/actionchunk/evaluate_act.py \
  --checkpoint myexperiment/actionchunk/outputs/act_flow_both_h5_seed0/best.pt \
  --split val --output myexperiment/actionchunk/outputs/act_flow_both_h5_seed0/eval_val.json

MUJOCO_GL=egl python myexperiment/actionchunk/rollout_act.py \
  --checkpoint myexperiment/actionchunk/outputs/act_flow_both_h5_seed0/best.pt \
  --task-id 8 --num-rollouts 40 --max-steps 270 --seed 0 \
  --temporal-aggregation --aggregation-decay 0.2 \
  --output myexperiment/actionchunk/outputs/act_flow_both_h5_seed0/rollouts
```

这两个入口均支持 `--flow-steps` 覆盖推理积分次数，例如比较 `5/10/20`，无需重训。
其余三种策略仍使用各自的 `evaluate_*.py` 和 `rollout_*.py`，自动恢复相机配置。
ACT 已有的距离分桶和输入消融入口同样使用新的模型加载逻辑。

## 指标与实验建议

ACT 新训练统一按 `val_prior_mse` 选择 `best.pt`：Transformer 用不看真实未来动作的 `z=0`；
Flow 用只以观测为条件、从噪声积分得到的动作。后验 reconstruction 仍保留用于诊断。
这修正了之前只按后验重建误差选择 checkpoint 与 rollout 条件不一致的问题；
已有 checkpoint 不会被转换或改写。

`val_flow` 是速度场误差；`val_prior_mse` 是最终生成动作误差，两者含义不同。
flow 训练不另外执行积分来计算训练集动作 MSE，因此 `train_reconstruction` 与
`train_prior_mse` 记录为 `null`（未计算），训练进度看 `train_flow/train_loss`。
验证噪声固定为 seed=12345，并在验证后恢复训练 RNG 状态；固定噪声只能减少验证波动，
正式结果仍需多训练 seed 与闭环 rollout。rollout 的 `--seed` 还用于固定 flow 的采样随机性。

建议逐项控制变量：

1. 固定相机、H、K 和数据划分，比较 ACT Transformer 与 Flow。
2. 固定动作头，比较 `none/agentview/wrist/both`。
3. 固定训练 checkpoint，比较积分步数和 aggregation 参数。
4. 多训练 seed 下汇报成功率均值、标准差和推理延迟。Flow 多次迭代可能更慢，需要一起记录。
